# 373 — the CG picture shows render exactly; index 255 in their PCX is a skip key

docs/363 §4 recorded a gap honestly: the warp route never plays the `na<stage>NNNN.pcx` picture shows or the ending
cards, so the arena-vs-PCX comparison never covered them.  docs/62's basis covers slide cards only.  This is the
measurement that closes the shows, and the two things that were in the way: a route that reaches them, and a
comparison that knew what it was looking at.

## 1. Reaching them

The Pocket host's warp route walks through the shows (docs/363 §4).  The SDL host's keyed route reaches them
(`scripts/playtest/route_show_keyed.txt`, docs/59 -- `130000 wait res na`, then a `space` press per picture, because
`fn_03a70e` turns the keyboard pump off and waits for one press per picture).  A dense variant
(`scripts/pocket/../playtest/route_show_dense.txt`, generated by appending `shot show_scan` every 500 ms across
130 000-160 000 ms) dumps the arena ~60 times across the show instead of at three keyed moments:

```
./build/night --script scripts/playtest/route_show_dense.txt --warp-stage 8 --shots /tmp/nad8 --no-audio --frames 9000
python3 scripts/pocket/show_cards.py /tmp/nad8
```

The shot dump carries the arena bytes under the name of the resource whose lookup just fired (`src/app/main.c:1147`),
and the manifest shows the show is short: `na80001` current over frames 2008-2063, `na80002` 2071-2172, `na80003`
2180-2253, with `stage8.wal_hold`, `st8s.spr_hold`, `8s1.pcx_hold`, `boss6.act_hold` loading underneath it.

## 2. Ruling out the boring explanations first

Measured against `na80001.pcx` at the best sample, 36 654 of 64 000 pixels differed (42.73 % agreement).  Every
explanation that would have made the comparison wrong rather than the render was tested and rejected:

| hypothesis | test | result |
|---|---|---|
| the shared PCX decoder ignores per-scanline RLE ends (only ever used on 640-wide cards) | row-aware re-decode | **identical numbers** (42.73 % both ways) |
| the card sits at an offset in a 640-wide canvas | stride 320/640 × x0 ∈ {0,160,320} × y0 ∈ {0,40,80,140} | best is still stride 320, x0 = 0, y0 = 0 |
| the arena is a cross-fade/checkerboard of two show cards | checkerboard of `na80001` with `na80002`/`na80003`, both parities | 41.8-42.5 % (no better) |
| the arena is a crop of the previous picture | crops of `8s1`, `stage8`, `title1` | 0.6-2.2 % |
| a multiplicative index ramp (the 0x19 fade, docs/62) | fit `port == (card*k)//256` for all k | best k = 256, i.e. identity, no gain |
| dither/neighbourhood diffusion of the same picture | is each differing byte a card value within 5×5? | **0.3 %** of them |

## 3. What the difference actually is

The counts line up exactly:

```
na80001:  differing pixels = 36 654 = the number of pixels the card encodes as index 255
          agreement at every position where the card is NOT 255 = 27 346 / 27 346 (100.00 %)
na80002:  differing = 24 587 = its 255 count; non-255 agreement 39 413 / 39 413 (100.00 %)
na80003:  differing = 24 380 = its 255 count; non-255 agreement 39 620 / 39 620 (100.00 %)
```

and the port never writes 255 at any of those positions (0 kept).  So **the picture-show loader treats index 255 as a
skip/transparent key** and writes every other byte of the shipped card exactly as shipped.  The show's 255 positions
are not simply "unchanged screen" either: they equal the previous shot's byte at only 2.8 % of them, i.e. the show
composites the card over content that is there for its own reasons.

`show_cards.py` now reports both readings, because reporting only the plain one calls a correct render "partial":

## 4. Two harness defects the same work exposed

- **`sweep_report.py` called a hand-run run "unclean".**  `crash = r["exit"] != "0"` read a *missing* `exit.txt`
  (only `sweep_episodes.sh` writes it) as a non-zero exit.  The 12 000-frame probe reported `clean=False` for runs
  that had simply reached their frame limit.  It now treats an unrecorded exit as unrecorded and says so on the
  verdict line.
- **The arena witness sampled the wrong frames.**  Every 8th frame with a 120-raw cap covers the first 960 frames
  and nothing else, so a 12 000-frame run bought time without buying coverage -- which is how the show gap survived
  being "measured" at all.  The stride is derived from the frame limit now (`witness arena stride=33 frames
  (cap 120 raws, covers 3 960 frames)`), and re-running the nine-stage sweep with it reproduces the same
  **27 distinct shipped cards** byte-identical (1s1..1s3, 2s1..2s2, 3s1..3s6, 6s1..6s3, 8s1, 9s1..9s3,
  stage1..stage9), `9/9 episodes entered and ran clean`.  The per-stage *sample* count drops (324 → 76) because
  spread sampling stops re-hitting the same card many times; distinct cards matched -- the number that means
  anything -- is unchanged.

## 5. Still open, stated precisely

- `gameove3.pcx` (an ending card): 3 604 differing pixels, and only 3 of them sit where the card is 255 -- so this
  one is a genuine 5.6 % difference, not the skip convention.  Next probe: sample the same card across a longer
  window (the ending card fades, docs/62's 0x19 ramp) and check whether a later frame closes the gap.
- `title1.pcx`: 0 % at the shot taken at frame 0 -- a shot-timing artifact (the card has not been written yet) or a
  .fli-driven title rather than a static PCX.  Needs the same longer-window treatment.
- The shows are verified as *rendered pictures*, not as *reachable content on the Pocket route*: the warp route still
  walks past them (docs/363 §4), so a Pocket player sees them only by playing normally.
