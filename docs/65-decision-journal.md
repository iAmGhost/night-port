# Decision journal

Decisions taken while porting and verifying NIGHT, with the reason and the measurement that justified each one.
Ordered roughly chronologically; each entry points at the doc that carries the detail.

| # | Decision | Why (evidence) | Doc |
|---|---|---|---|
| 1 | Port function-by-function from Ghidra output, keeping the original control flow and its quirks | A structural rewrite hides transcription errors; keeping quirks made the latent NULL-dereference and dead-slot bugs findable instead of silently "improved" | docs/12 series |
| 2 | Keep heap allocations as **arena offsets**, not host pointers | The shipped code stores offsets in struct fields (`+0x04..+0x38` of every `.spr` block); mixing the two conventions produced the game-over SIGSEGV when a raw offset was used as a pointer | docs/49, docs/61 |
| 3 | Model hardware interrupts **cooperatively** (`sys_port_spin()` in every busy-wait) | The port is single-threaded; a busy-wait without a pump deadlocks the game. The stage-8 picture show wedged exactly there (`fn_03a70e` key wait) | docs/52 |
| 4 | Implement the `0x3DA` retrace wait as a real wait to the next retrace boundary | The logo hold, slide fades and the "melting" title are all paced by that wait; a stub made them flash past. Measured: pacing is now clock-anchored (stage load within 0.13 s across runs) | docs/47, docs/54 |
| 5 | Initialise `DAT_00053338` to 1 (as shipped), rather than "fixing" it | The shipped NIGHT.EXE has the byte set; the port's `= 0` silenced every DSP transfer. Verified by reading DS `0x53338` in the image (cross-checked against neighbours: `0x53334`=0x210, `0x51a10`=1, `0x53340`="Stack Overflow!") | docs/55 |
| 6 | Bring up audio through a device ladder + software sink, and bind every stream | A broken CoreAudio device (`AudioQueueStart 2003329396`) on this machine must not wedge boot; SDL3 requires `SDL_BindAudioStream` or streams fill but never reach hardware (98 KB backlog -> 261 KB submitted after the fix) | docs/55, docs/57 |
| 7 | Treat `fn_010b1d` as the CD-DA track-start request (EAX *is* an argument) | Ghidra conflated it with the stack canary; the disassembly (`0x010b35 MOV [EBP-4],EAX`) and the MSCDEX `0x1510` media read prove it. On-disc audio sectors measured little-endian S16 (lag-1 autocorrelation 0.982/0.972 vs ~0 for big-endian) | docs/57 |
| 8 | Playtest with **game-anchored** scripts (`wait res NAME`) instead of wall-clock delays | Script keys were landing in the wrong game phase once audio changed pacing; anchoring on resource lookups made runs reproducible to +-3 ms across audio states | docs/56 |
| 9 | Reach unreachable screens with a host **debug warp** into the game's own routine (`NIGHT_SHOWSCREEN`) | Level-up, help, status and game-over are gated by progression the scripted route cannot force; the warp enters the shipped routine, so loading, compositing and key handling stay original | docs/61 |
| 10 | Close the DOSBox frame-capture route as a measured dead end on this machine | Five routes measured: `screencapture` all-black even with a Metal window; System Events sees no window; 0.83 has no `capjpg`/`cappng`/capture CLI (`Illegal command: capture`); no file-backed serial/LPT; in-guest TSR writes land only from the install context because NIGHT owns the timer through its protected-mode IDT | docs/46 |
| 11 | Substitute reference = the **shipped asset decoded independently**, compared against the port's screen arena | With no original frames available, byte-level agreement against the shipped data is the strongest available claim. It proved logo/slides/help/continue byte-identical, level-up 1.06-1.38 % (all in its number column), game-over 95.1 % of pixels from shipped layers, pause-menu composites 547,781 bytes with 0 mismatches | docs/62, docs/63, docs/60, docs/61 |
| 12 | Withdraw, rather than patch, checks built on guessed argument orders | An invented cell convention drew nothing for `mboss3` cell 1; guessing is what caused the game-over crash. The gap is filed with a root cause instead | docs/64 |
| 13 | When a report disagrees with measurement, re-measure before fixing | Two filed defects closed as measurement artifacts (the EFFECTS glyph toggle; the level-up assets "not loading" - the warp simply had not been enabled) | docs/60, docs/61 |

| 14 | Charge the A0000 window write **once per page flip** in the room path, not at the blitter | The arena map (`video_map`) shows the background plane, entity sprites, glyph/number displays and the gauge all write the off-screen `g_screen_ram` screens; only `cpy_dw(..., g_video_ram)` touches A0000, so charging the blitter would double-count RAM work. Measured with the new `NIGHT_FRAMERATE=1` diagnostic: 70.0 calls/s drawn at `NIGHT_VGA_WS=0..223` ns/byte, shedding engages above ~223 (50.8 drawn at 300); the flip costs 4.03-6.24 ms of the 14.29 ms frame budget at the shipped cadence (PIT ch0 divisor 0x982 = 490 Hz, `DAT_53104`=70, so n=7 ticks/frame). A/B on the title melt and logo shows no regression: 6002 vs 6005 ms ramp, 2603 vs 2592 ms logo | docs/76 |
| 15 | Never quote a fitted gain without its premise check (colour-set share, index agreement, channel order) | The "settled title palette gain" evaporated: the port reproduces the shipped palette verbatim (per index (41,8,8)->(40,8,8) = the 6-bit DAC quantisation), while the original side's ~0.79 gain had been fitted to a capture that contained **zero** card-palette colours (exact-card-colour share 0.000 in both channel orders; 1->42->98->149->159 distinct colours = a transition, not a settled card), and per-channel fits are impossible for a DAC fade. A gain-fitted NCC of a non-matching pair looks convincing and means nothing | docs/77 |
| 16 | Host debug warps are **gated** on the shipped preconditions and **defer** instead of firing | `NIGHT_SHOWSCREEN=gameover` with `AT=1500` segfaulted (ASan: SEGV at address 0x48, `fn_0406f5` <- `fn_038445` <- `tick_pump`) because `fn_038445` opens by fading the current room's palette out of `DAT_63354+0x48`, and its only in-game call site (`0x0003aecf`) is inside the room loop, so `DAT_63354` is never NULL there. `fn_showscreen_gate()` returns the missing state; post-fix the pre-room warp defers and never fires, `--warp-stage 1` defers at 1533 and fires at 2572, SEGV count 0 | docs/78 |
| 17 | Channel order is a property of the **capture configuration**, not of the video mode; print an orientation anchor beside every original-side score | Re-scoring audit: the settled stage-1 pair was NCC 0.9928 / 1.26 % within +-3 on the mirrored basis and is **100.0000 % within +-3, MAE 0.17** once corrected (the "different game states" explanation was wrong); the pause menu 0.87 -> 86.18 % / NCC 0.860 / MAE 9.04; but the mode-13h `.fli` pairs were proven *unaffected* (100.00 % as published vs 0.67 %/4.65 % swapped, R==B on only 0.7-4.7 % of pixels), so "mode 13h => BGRX" cannot be assumed | docs/70, docs/79 |
| 18 | A draw census must report **loaded vs composited**, not just composited | With `NIGHT_RESLOG` alongside the content attribution: every family previously called "not observed" **is loaded by the game's own loader inside that episode** (ep1 20 loaded / 17 never composited incl. `boss1`, `enc-1/2`, `st1s`, `system`; ep9 23/21 incl. `boss7`, `eni-1..4`, `enj-1..4`), so the gap is entity position and phase, not a port omission. Walking and firing composited no new families, which is itself the finding | docs/80 |
| 19 | Drive the ORIGINAL's transitions by writing its own state variable **while the owning loop is live** | `DAT_0006336c = 1` ("gone for good", tested at `0x0003abc0`) written on a 640x480 card was never consumed (`read back 1`, still 1 twenty seconds later, credits 3); written in a live room it was consumed on the next sample (`read back 0`) and the CONTINUE screen appeared. That path reproduced the shipped screen exactly: port vs original **99.66 % within +-3, MAE 0.36, NCC 99.26 %**, the 138-pixel residual confined to the blinking YES/NO marker | docs/81 |
| 20 | Original-side mode pacing must require the mode to **hold**, not to appear once | A press landing as the episode's picture show ends makes the game flash mode 13h for a single sample and then fall back to a 640x480 card forever (`stage` one 320x200 frame, then 640x480 for the rest of the run, `DAT_63354` non-null). `key_until_mode_stable ... 4` fixed three lost runs: 302 of the remaining 320 frames are gameplay | docs/81 |
| 21 | When the thing being compared is a **phase**, pin the phase before scoring | docs/74's episode-8 window (4.53 % within +-3, NCC 0.197) was the original's once-per-room CG dialogue card (`na80001.pcx` content, identified by **identical per-colour occurrence counts** 1246/891/790/640/463/395 with colours a few LSBs apart, and the card's teal key on 0.00 % of window pixels) scored against a **post-show** port frame. Aligned, the port's show frame is **100.00 % within +-3, MAE 0.24, NCC 100.00 %**; the docs/74 number reproduces at 4.48 % / NCC 20.93 %. `scripts/playtest_ep8_show.py` now pins the phase (>= 99.5 % floor, currently 100.00 %) | docs/82 |
