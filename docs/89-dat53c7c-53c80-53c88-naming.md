# DAT_00053c7c / 0x53c80 / 0x53c88 (and 0x63370): what they really are

Goal task `ghidra-dat53c-naming`. The question was left open in docs/78/docs/81: the guest reads
`DAT_00053c80 == 0` inside a live room while `DAT_00053c7c == 0x00631798`, which did not match the
port's reading of `DAT_00053c80` as "the entity whose death announces `DAT_0006336c = 3`", and the
port's own header still carried the pre-analysis guess *"kb config ptr"* for `DAT_00053c7c`.

## Method (all headless, reproducible)

1. Ghidra cross-reference census over the four globals (ghidra-mcp against `NIGHT.EXE`):

   ```text
   get_xrefs_to 0x53c7c -> 869 refs, of which WRITE = 2
   get_xrefs_to 0x53c80 ->  10 refs, of which WRITE = 2
   get_xrefs_to 0x53c88 ->   9 refs, of which WRITE = 6
   get_xrefs_to 0x63370 ->  42 refs, of which WRITE = 3
   ```

2. The ported room loop already carries the shipped addresses of every read of the arming test
   (`port/src/f/f.c`, `fn_03a829`, the block annotated `0x0003aa3b-0x0003aa9a`).
3. The original-side witness comes from the docs/81 dosbox-automation harness (memory API, data base
   `0x205000`, code delta `0x1ba000`): in a live episode-1 room `DAT_00053c7c = 0x00631798`
   (an absolute heap pointer) and `DAT_00053c80 = 0`.

### What the picture-show arming at `0x0003aa3b` really tests

`fn_03a829` (the room frame loop) arms the once-per-room CG slide show `fn_03a70e` when the *latched*
entity exists **and is inside the camera band**:

```c
if (showed == 0 && g_latched_ent != NULL &&
    (int32_t)g_dat_639e0 <= *(const int32_t *)(g_latched_ent + 9) &&      /* Y in [camY, camY+200) */
    *(const int32_t *)(g_latched_ent + 9) < (int32_t)g_dat_639e0 + 200 &&
    (int32_t)g_dat_639dc + 0x32 <= *(const int32_t *)(g_latched_ent + 1) &&/* X in [camX+0x32, camX+0x10e] */
    *(const int32_t *)(g_latched_ent + 1) <= (int32_t)g_dat_639dc + 0x10e)
    fn_03a70e();
```

Read sites of `DAT_00053c80`: `0x0003aa31 / 3aa3c / 3aa4c / 3aa64 / 3aa77` (exactly that test),
`0x00015328` (`fn_015295`: when *that* entity dies `DAT_0006336c = 3`), `0x000129fc` (`fn_012616`),
`0x000150cb` (`fn_01441e`).

### Reconciled with the measured guest witness

`DAT_00063370` is the episode counter, so the latch only fires for an entity **constructed with
`type index == the current episode number`** (episode 1 -> type 1 = `boss1.spr` in the EXE's per-type
name table, …, episode 7 -> type 7 = `boss7.spr`; the table has plain `gun.spr` at types 8 and 9, which is
why episodes 8-9 do not arm the show through this latch). A scripted walk that never reaches that
constructor therefore leaves `DAT_00053c80 == 0` — exactly what the guest showed — while
`DAT_00053c7c` (the player) is a live heap pointer. Both witnesses are consistent with the resolved
semantics; nothing in the port needed a behaviour change, and docs/81's conclusion stands: the reliable
way to drive an original-side transition is to write the game's own state variable
(`DAT_0006336c = 1`) while the owning loop is live, not to wait for the entity route.

Two port-side details the naming pass also pins: `DAT_00053c88` is stored **DS-relative** in the
original while `DAT_00053c7c`/`DAT_00053c80` hold real pointers — the port keeps that split
(`g_gauge_other_off = (uint32_t)(uintptr_t)(cur - hb)` at `0x000147f0-0xfb`), and
`DAT_00053c84` (`fn_0376c8`, `0x377d4`) is the DS-relative copy of the player block.

## Renames applied

* Ghidra (`set_global`, program saved): `DAT_00053c7c -> g_pPlayerEntity` (`void *`),
  `DAT_00053c80 -> g_pLatchedTypeEntity` (`void *`), `DAT_00053c88 -> g_dwGaugeOtherEntityDs`
  (`uint`), `DAT_00063370 -> g_dwEpisodeCounter` (`uint`), each with the write/read-site plate comment above.
* Port: `g_dat_53c7c -> g_player_ent` (326 sites), `g_dat_53c80 -> g_latched_ent` (56),
  `g_dat_53c88 -> g_gauge_other_off` (33) — 415 identifier sites across `src/f/f.h`, `src/f/f.c`,
  `src/app/main.c`, `test/test_f1.c`, with the shipped `DAT_…` address kept in every declaration
  comment so existing docs citations stay greppable. No behaviour change.

The latching rule itself was already pinned by the suite before this pass
(`fn_010efc … "type index == DAT_63370: published to DAT_53c80"`), and docs/84's new host entity warp
test (`test_warp_entity_shared_types`) now additionally asserts `g_dat_63370`-independent spawning.

## Follow-up this unlocks

`NIGHT_WARP_ENTITY=boss1` in episode 1 (`DAT_00063370 == 1`, so type 1 == the counter) latches
`g_latched_ent` legitimately, which means the CG picture show can be armed in the port by spawning the
episode's own boss type instead of a host hack — a cleaner route for the docs/52 / docs/82 show
captures, and worth checking when the original-side show timeline (docs/85) is measured.
