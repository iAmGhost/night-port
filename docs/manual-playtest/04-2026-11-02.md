- [x] **1. Music now changes, but there is an audible delay.** The track does switch on this build (the older
      complaint in `03-2026-10-29.md` item 1 is gone), yet the change is heard noticeably after the game asks
      for it.
  * **Verdict: real defect, fixed in two halves** ✓
    * Rate half ✓ `cdda_pump()`'s device-bound branch asked for a fixed 30 sectors on *every* pump call while the
      pump runs ~100 times per frame, so it fed **3.64x** real time (53,311 sectors = 710.8 s of audio in a
      195.4 s run, `/tmp/rig/le8`) ✓ fixed with a wall-time sector budget → **1.04x** ✓ docs/302 ✓
    * Latency half ✓ the reader was bounded against *elapsed time* and never against what the **device had
      consumed**, and `cdda_play()` flushed the stream only when the outgoing track still had sectors ✓ so the
      stream ended up holding **3.75 MB = 19.5 s** of audio and each switch queued **4.17-9.96 s** of old track in
      front of the new one (`/tmp/rig/mt1`, `/tmp/rig/mt2`; 3 of 4 switches took no flush at all) ✓ fixed by
      making the 30-sector cushion the queue ceiling and flushing unconditionally → **0.35-0.44 s**, peak queue
      **0.60 s**, feed still 1.04x, 0 underruns (`/tmp/rig/mt4`, `/tmp/rig/mt5`) ✓ docs/307 ✓
  * Instrument now in the port: `NIGHT_CDDADBG=1` writes `cdda_pipe.jsonl` (`SDL_GetAudioStreamAvailable`,
    pushed/pulled, play/flush/first_feed markers) ✓ read by `scripts/rig/cdda_delay.py` ✓
  * Gate note ✓ music *content* cannot be compared with the shipped side on this harness: the container's
    `audio.wav` is an emulator mixer capture that contains **no CD-DA at all**, so its correlation floor
    (0.07-0.21) is not a port defect ✓ docs/304 ✓ docs/305 ✓ Music is gated on schedule + stream rate + disc-byte
    identity instead ✓ all three are green (`(1,37262,3153) (9,185120,27697) (11,223146,17856) (2,40415,19639)`
    identical before/after ✓ 273 `[SAME]` onset windows ✓ `disc_search.py` NCC **+1.000** at disc sector 37337 ✓)
  * Shots: none (audio) ✓ witness paths `/tmp/rig/mt1..mt5/cdda_pipe.jsonl`, `/tmp/rig/le8`, `/tmp/rig/rb15` ✓

- [x] **2. One attack make lands several hits on the same enemy at once.** A single attack keypress appears to
      damage one enemy multiple times simultaneously.
  * **Verdict: real defect, fixed** ✓ the duplicate is caused by `fn_01441e`'s action-row selection rule as changed
    by docs/263 ✓ that doc read `0x14685 jg 0x1469f` as a jump to the accept block, but `0x1469f` is a two-byte
    `jmp 0x146a9` -- the **next-row** path ✓ so the shipped *skips* a row whose start threshold is above the frame
    counter, and its rule is `w1 <= fr && w2 > fr` ✓ the very conjunct docs/263 deleted as "invented" ✓ docs/306 §2
  * Why that produces repeats ✓ the shipped dedupes per victim on the pair *(attacker state, accepted row)* --
    `0x14700-0x14719` skips a victim whose `+0x4e/+0x4f` match the current state and slot, and `fn_01441e` writes
    that pair at `0x14812/0x1481b` ✓ the port models both halves (`f.c:25394-25395`, `f.c:25433-25434`) ✓ but a
    selection that admits not-yet-live rows hands a different slot to every pass, so the key never repeats and the
    victim absorbs one hit per pass ✓
  * Oracle: `scripts/rig/hits_per_attack.py` (dump-side ✓ identity = `(record offset, kind, span)` ✓ hit = a fall of
    the victim's `+0x23`, the field `field_writers.py` shows has exactly one subtractor, `0x14964`) ✓ before: one
    victim hit 2x and 3x inside one make, and a latch-key miss -- two falls inside a single attack state
    (`/tmp/rig/h306/head2`, ticks 981/982 in state `0x35`, `23->9` then `9->2`) ✓ after: 0 latch misses in either
    repeat, and post-fix two-hit makes span two states (`0x34` then `0x35`) which the shipped's key permits ✓
    fixture red on the unfixed line and green after (`make -C port test` = ALL PASS) ✓ docs/306 §1, §5 ✓
  * Docs: docs/306 ✓ docs/263 (the relaxation, now reverted) ✓ docs/249, docs/252, docs/246 (field semantics) ✓
  * Shots: none (combat arithmetic) ✓ witness paths `/tmp/rig/h306/{head1,head2,base1,base2,fix1,fix2}` ✓
